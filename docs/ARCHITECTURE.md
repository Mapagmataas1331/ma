# Architecture

Four static Vite apps share `@ma/ui`, `@ma/i18n`, and `@ma/content`. Chat also uses `@ma/crypto`, `@ma/protocol`, and `@ma/api-client`.

`services/api` is one Go process: REST, WebSocket signaling, presence in memory, temporary mailbox on local disk, cleanup every 10 minutes. PostgreSQL holds accounts, devices, contacts, conversations, and mailbox metadata. There is no Redis.

Online text and files use WebRTC data channels. When someone is offline, files wait in that sender's cloud: one ciphertext on disk, linked to every recipient, counted once against a 5 GB sender budget (messages are not counted). The file is removed after 24 hours, when every recipient has downloaded it, or when the sender deletes it. A file larger than the remaining budget is refused with a list of what is using the space. Any member who has a copy can hand it to another member; if several do, the sender with the lowest round-trip time is used. A file bigger than 5 GB is sent only to people who are online. A file that fits the budget but not the remaining space asks whether to free cloud space or send only to people who are online. A member who was offline and comes online while the file is still being sent gets it from whoever already has a copy, and from the cloud when a copy was stored. Files sent while everyone is online never touch the server: the sender encrypts them once into its own OPFS store and streams that ciphertext over the data channel, 64 KB secretstream chunks at a time, pausing on `bufferedamountlow` so a slow receiver does not blow up memory. Because the ciphertext and its key live in the sender's vault, a sender can keep sharing after a reload or reconnect for as long as the file fits its storage budget. Receivers probe (`chat.file.probe`) before showing a large file as available.

Local history is field-encrypted in IndexedDB under a random DEK wrapped by an Argon2id key from the vault password. The server never sees that key. Each account uses its own database, `ma-chat-v2:<user-id>`, plus an OPFS directory `users/<sha256(user-id)>/files` for file ciphertext; the per-file key, header, and chunk lengths are sealed under the DEK in the `files` table. Browsers without OPFS fall back to base64 rows for files up to 32 MB. A legacy unowned `ma-chat` database is copied only when its identity public key matches the signed-in account.

Storage is one budget per account and device, default 5 GB, covering message rows, cached files, and the outbox queue. There is no per-file cap: anything that fits is kept, and when the budget is exceeded the oldest files go first and their messages are dropped. The user can raise, lower, or disable the budget in settings, and a "clear all local data" action, available before the vault is unlocked, removes every database, OPFS directory, cache, and service worker for the origin, including data from older versions.

Direct chats encrypt one envelope to the peer identity. Group chats fan out one envelope per member, with a maximum of 20 members, and do not use a shared group key. Device transfer moves the DEK and identity keys over a WebRTC data channel after a trusted device confirms a short-lived pairing code. Pending devices can open that pairing socket, not conversations, mailbox, or TURN.
